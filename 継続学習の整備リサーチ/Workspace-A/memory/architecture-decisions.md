# 設計判断

## ADR-001: 方針と現在地を Markdown で引き継ぐ
- 状態: 本サンプルで採用。
- 背景: セッション B がセッション A の会話にアクセスできるとは限らない。
- 決定: 継続方針・教訓・設計判断・現在地を分けて保存する。
- 代案: 会話を毎回貼り付ける。サービス独自の記憶機能を前提にする。
- 理由: 人が確認・編集でき、同じファイルを次のセッションへ渡せる。
- 影響: 更新と読込が必要。保存していない会話や推論は復元できない。

## ADR-002: hooks は参考例だけを同梱する
- 状態: 本サンプルで採用。
- 決定: `.json.example` を使い、自動検出される `.json` を配置しない。
- 理由: 対象の VS Code・Copilot・セッション実装での実動作を検証していないため。
- 影響: 自動の記憶更新は行われない。まずチャットから明示的に引き継ぐ。

## 新しい判断の記録形式
ID / 日付 / 状態（提案・採用・廃止・置換）/ 背景 / 決定 / 代案 / 理由 / 影響 / 置換先。
